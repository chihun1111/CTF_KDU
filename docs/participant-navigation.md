# 참가 동선·난이도·URL 구성

참가자는 메인에서 난이도를 보고 문제를 선택한 뒤 해당 문제의 실제 화면에서 시작한다.
각 문제의 상세 조회·검색·자료는 같은 번호 아래에 두며, 다른 문제를 경유하는 연결을 줄였다.
이 문서는 현재 경로와 유지보수 계약을 설명한다. **새 변경의 확장 브라우저·CI 검증 결과는 아직 기록하지 않았다.**

## 참가 흐름

1. `/`에 접속해 참가 방법과 네 단계 난이도 안내를 확인한다.
2. 회원가입하거나 로그인하면 같은 메인에 활성 문제 목록이 표시된다.
3. 번호·난이도·분야·설명을 보고 **문제 풀기**를 누르면 실제 풀이 화면이 바로 열린다.
4. 문제 내부에서 단서를 조사하고 찾은 값을 따로 보관한다. 문제 목록으로 돌아와 다른 문제를 선택한다.
5. `/submit`에서 일부 값부터 확인하고, 마지막에는 8개 값을 함께 제출한다.
6. 완료 후 한 번 표시되는 인증 화면에서 촬영 안내를 확인한다.

가입에 필요한 필수 동의와 선택 동의는 구분한다. 난이도 표시는 출제자의 선수 지식 추정이며,
실제 학생의 성공률·풀이 시간 측정 결과가 아니다. 문제 번호가 풀이 순서를 강제하지 않는다.

## 공통 경로

| 역할 | 경로 | 화면 또는 동작 |
| --- | --- | --- |
| 메인 | `/` | 로그인 전 참가 안내, 로그인 후 활성 문제 목록 |
| 회원가입 | `/register` | 참가 계정 생성 |
| 로그인 | `/login` | 기존 계정으로 참가 |
| 제출 | `/submit` | 최근 제출 판정과 8개 전체 완료 확인 |
| 힌트 | `/hints` | 운영자가 공개한 단계의 힌트 |
| 인증 | `/clear` | 전체 완료 후 1회 표시되는 인증 화면 |

문제의 정식 진입 주소에는 끝의 `/`를 포함한다. 메인 버튼은 이 주소를 직접 사용한다.
끝의 `/`를 빠뜨려 입력하면 Nginx가 같은 문제의 정식 주소로 308 이동시킨다.

## 문제별 난이도와 주소

| 번호 | 문제 | 난이도 | 분야 | 정식 URL |
| --- | --- | --- | --- | --- |
| 01 | 캠퍼스 축제 안내 | 입문 · 1 | Web / Misc | `/challenges/01/` |
| 02 | 서비스 상태 | 초급 · 2 | Web | `/challenges/02/` |
| 03 | 과제 제출 확인 | 초급 · 2 | Web | `/challenges/03/` |
| 04 | 동아리 운영 현황 | 초급 · 2 | Web | `/challenges/04/` |
| 05 | 동아리 홍보 페이지 | 입문 · 1 | Frontend | `/challenges/05/` |
| 06 | 빌드 자료 보관함 | 초급 · 2 | Frontend | `/challenges/06/` |
| 07 | 자유게시판 | 중급 · 3 | Web / DB | `/challenges/07/` |
| 08 | 특별상 수령 안내 | 고급 · 4 | Web / Crypto | `/challenges/08/` |

입문은 페이지와 배포 자료의 기본 탐색, 초급은 주소·요청·브라우저 상태 관찰,
중급은 입력과 데이터 처리 분석, 고급은 해시·서명 관련 선수 지식을 기준으로 구분한다.

## 문제 내부 이동

03의 상세 조회와 07의 검색 결과처럼 풀이에 필요한 동작은 해당 문제 안에서 유지한다.
문제의 공통 머리글은 메인의 문제 목록으로 돌아간다. 별도 문제 소개 화면을 거쳐
같은 풀이 화면을 다시 여는 동선은 참가자 버튼에 연결하지 않는다.

05의 자바스크립트에서 06의 소스맵으로 이어지던 참조를 제거했다. 06은 자기 보관함의
공개 자료에서 시작하며, 1차 힌트도 해당 보관함의 파일 형식과 내용을 살펴보도록 안내한다.

## 제출 화면

결과는 최근 제출 한 건 기준이다. 새로고침하면 입력값이 비워지므로 찾은 값을 별도로
보관한다. 부분 확인 결과를 제출 간 합산하지 않으며, 최종 완료에는 8개 값이 한 번에 필요하다.
칸 위치와 실제 문제 번호가 달라도 서버가 일치하는 항목을 판정한다.
모바일에서는 입력칸을 채운 뒤 아래에 있는 최종 제출 버튼을 사용할 수 있다.

## 기존 URL 호환

| 이전 기본 경로 | 새 기본 경로 |
| --- | --- |
| `/campus/festival/` | `/challenges/01/` |
| `/system/status/` | `/challenges/02/` |
| `/student/assignments/` | `/challenges/03/` |
| `/clubs/admin/` | `/challenges/04/` |
| `/clubs/security/` | `/challenges/05/` |
| `/clubs/build-archive/` | `/challenges/06/` |
| `/community/board/` | `/challenges/07/` |
| `/bonus/vault/` | `/challenges/08/` |

예전 문제 주소는 뒤의 경로와 쿼리 원문을 보존하는 308 응답으로 새 주소에 연결한다.
`/hub`는 `/`로, `/services/<slug>`는 해당 문제의 정식 URL로 이동하는 호환 경로다.
실제 참가자 UI는 처음부터 정식 URL을 사용한다. 08의 경로 쿠키는 자동 이전하지 않으므로
전환 후 새 티켓으로 시작해야 한다. 자세한 운영 영향은 [운영 가이드](operations.md)를 따른다.

## 유지보수 계약

- 공개 번호·제목·난이도·분야·URL의 단일 출처는
  [shared 카탈로그](../packages/shared/src/challenge-catalog.ts)다. 프런트와 backend는 공유 타입을 사용한다.
- [목록 API](../apps/backend/src/challenges/challenges.service.ts)는 활성 상태이면서 카탈로그에 등록된 항목만
  반환한다. DB 식별값·개인별 정답·내부 통신 경로를 공개 메타데이터에 넣지 않는다.
- 경로 변경 시 [Nginx](../infra/nginx/nginx.conf), 문제의 공개 자산·폼·쿠키 경로,
  [힌트](../apps/backend/src/hints/hint-definitions.ts), 실행 검사와 브라우저 검사를 함께 맞춘다.
- 새 문제 버튼이나 자산 참조는 같은 번호 아래에 두고, 다른 문제로의 연결이 꼭 필요한지 검토한다.
- 참가자 난이도와 실제 풀이 경로의 차이는 학생 관찰을 통해 조정한다. 자동 검사 시간을 사람의 풀이 시간으로 쓰지 않는다.

## 검증 범위와 상태

확장 검사는 아래 계약을 대상으로 한다. 이 문서 작성 시점에는 새 브라우저·전체 CI의
실행 성공을 선언하지 않는다. [브랜치 실행 기록](https://github.com/chihun1111/CTF_KDU/actions?query=branch%3Aimprove%2Fproject-hardening-2026-11-16)에서
대상 커밋의 결과를 확인한다.

| 검사 대상 | 확인할 내용 |
| --- | --- |
| 공개·로그인 메인 | 참가 안내, 인증 후 목록, 난이도·분야 표시 |
| 직접 진입 | 메인에서 8개 실제 문제로 이동, 중간 소개 화면·다른 문제 경유 없음 |
| 경로 일관성 | 공개 자산·폼·복귀 링크, 기존 주소 suffix/query 보존, 08 쿠키 Path |
| 문제 독립성 | 05→06 연결 제거와 06 자체 자료·힌트 |
| 모바일 | 주요 링크 노출, 페이지 폭, 입력 후 제출 버튼 |
| 기존 회귀 | 8개 문제 풀이, 참가자 격리, 부분·전체 제출, 인증 1회 소비 |

브라우저의 정상 흐름 확인과 처음 접한 참가자의 난이도 평가는 구분한다.
이전 관찰은 [풀이 진행성 보고서](playability-review-2026-11-16.md)에 역사 기록으로 남긴다.
