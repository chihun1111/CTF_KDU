# 엄격 재검증 및 추가 보강

검토 기준은 2026-11-16(Asia/Seoul)의 main 구현 `2d55037`이다. 인증·관리자 조회·
프런트 요청 처리·8개 문제·배포 검사를 나눠 검토하고, 재현한 실패를 수정했다.
교육용으로 의도한 문제 풀이 방식과 참가자 URL·난이도 표시는 유지한다.

## 이번에 적용한 비밀번호 규칙

사용자 요청에 따라 **가입과 로그인 모두 ASCII 영문 대소문자·숫자 8~128자**만 허용한다.
문자 종류를 혼합하도록 강제하지는 않는다. 이모지, 한글, 구두점·기호, 모든 ASCII 제어문자,
공백, NUL, 개행, JSON null과 문자열이 아닌 값은 거부한다. 허용되지 않은 입력을
잘라내거나 정리한 뒤 인증하지 않는다. HTML 입력 제한·안내·프런트 검증·서버 DTO를 맞췄다.

기존 특수문자 비밀번호 계정도 로그인 단계에서 새 규칙을 적용받는다. 기존 계정이나
해시는 자동 변경하지 않았으며, 실제 계정이 있는 환경은 배포 전에 전환 절차가 필요하다.
현재 비밀번호 재설정 UI는 없다. 자세한 영향은 [운영 가이드](operations.md)를 따른다.

## 재현한 문제와 수정

| 영역 | 재현한 실패 | 영향과 수정 |
| --- | --- | --- |
| 감사 로그 | nullable JSONB metadata를 객체로 취급해 NULL 행에서 예외. prototype 이름 action이 허용 키 맵의 상속 속성에 접근 | 관리자 조회 장애. 비객체 metadata는 빈 객체, 등록된 action의 승인된 키만 출력 |
| 최근 제출 | 같은 시각의 제출에서 참가자는 시각만, 관리자는 시각·ID를 기준으로 정렬 | 최신 점수·결과 불일치. 두 조회를 `created_at DESC, id DESC`로 통일 |
| 인증 입력 | 고립 surrogate와 대체 문자가 UTF-8 인코딩 후 같은 해시 재료가 됨. 일부 긴 Unicode 비밀번호는 입력창에서 잘림 | ASCII 허용 목록을 가입·로그인에 적용해 비정상 인코딩과 입력 범위 차이를 제거 |
| 학번 | 7자리 뒤 개행이 붙은 값이 정규식의 끝 조건을 통과 | 비정규 학번 생성·인증 가능성. 문자열의 절대 끝까지 정확히 7자리인지 검사 |
| 프런트 서버 요청 | 업스트림 오류 응답 본문을 읽거나 취소하지 않고 반환 | 기존 10초 timeout 또는 GC까지 불필요하게 스트림·연결 유지 가능. 본문 취소, 원래 상태·헤더 보존, 재시도 없음 |
| 08 티켓 | hex 디코더가 잘못된 접미사·홀수 마지막 nibble을 잘라내 동일 서명으로 인정 | 잘못된 티켓 형식 허용. 정확한 64개 hex 문자만 디코딩하며 의도된 풀이 성공 회귀 유지 |
| 배포 정책 검사 | 다른 네트워크 연결, 과도한 권한, 추가·상속 마운트, 상충 tmpfs 옵션을 정상으로 판정 | 검사 누락. 네트워크·권한·secret·마운트 계약을 엄격하게 검사 |
| 실행 상태 검사 | 같은 서비스의 마지막 컨테이너만 확인하거나 health 결과 누락을 허용 | 비정상 복제본·누락된 상태 검사를 놓침. 모든 행과 설정된 healthcheck 결과 확인 |
| 선택적 관리자 smoke | 현재 API의 `onlineSessionCount` 대신 과거 필드 검사 | 정상 서버를 실패로 판정. 현재 응답 계약을 검사하고 관리자 옵션 회귀에 포함 |

수정 전 실패를 확인한 회귀 검사를 수정 후 다시 실행했다. 배포 검사 관련 발견은
**잘못된 설정을 검사기가 놓친 사례**이며, 현재 포함된 Compose 환경에서 실제 컨테이너
탈출에 성공했다는 의미는 아니다. 08 서명 형식 문제도 단독 권한 상승으로 입증한 것은 아니다.

## 추가한 실동작 검증

- **실제 HTTP 처리:** 8개 문제에서 업스트림 오류·잘못된 JSON·다른 문제 ID·잘못된 flag 타입을 주입하고,
  세부 오류가 노출되지 않는 503, no-store, health 유지 여부를 확인한다.
- **SQLite 격리:** 07의 기존 격리 검사에서 다른 참가자의 동시에 열려 있는 DB 경로를 알아도
  `ATTACH`가 거부되는지 확인한다. 의도된 입력 취약점, 제한 시간, 메모리·출력 제한 검사도 유지한다.
- **공개 진입점:** 위조 신원 헤더·잘못되거나 중복된 쿠키·cross-origin 변경 요청·잘못된 입력을
  Nginx를 통해 검사한다. 로그아웃 이후 같은 쿠키로 8개 문제에 재접근할 수 없어야 한다.
- **실제 PostgreSQL:** 일회성 CI 스택의 새 참가자에게만 nullable·비객체 감사 metadata와
  같은 시각의 제출을 넣고, 관리자 화면 정상 응답·허용 필드 제한·참가자 점수 일치를 확인한다.
- **동시 인증서 요청:** 같은 일회성 쿠키로 두 요청을 동시에 보내 한 요청만 인증 화면을
  얻는지 확인한다. 패자와 재사용 응답에 참가자 식별 정보가 없어야 한다.
- **브라우저:** 기존 데스크톱·모바일 참가 시나리오에 비밀번호 허용·차단 경계를 추가했다.
  128자 영문·숫자 비밀번호로 가입과 재로그인이 성공해야 한다.

예전 artifact controller는 소스만 남아 있고 서버 모듈에 등록되지 않았음을 확인했다.
신규 취약점으로 집계하지 않으며, 8개 현재 slug의 외부 404 검사를 추가했다.

## 실행 방법과 증거

통합 전 로컬 검사 결과는 전체 테스트 **388개 통과**, 전체 빌드·타입 검사 통과,
민감 자료 검사 345개 파일 통과다. 문서 링크와 UI 문서 정책 검사도 통과했다.
이 수치만으로 Docker 실행 검증을 대신하지 않으며, 아래 두 workflow의 해당 커밋 결과를 함께 확인한다.

전체 테스트·빌드·타입·민감 자료·의존성 검사는 [CI](../.github/workflows/ci.yml),
Docker·PostgreSQL·브라우저·경계·장애 복구 검사는 [Runtime integration](../.github/workflows/runtime.yml)에 연결했다.
각 실행 결과는 해당 코드 커밋의 GitHub Actions 기록을 기준으로 확인한다.

```bash
corepack pnpm test
corepack pnpm build
corepack pnpm typecheck
corepack pnpm verify:sensitive
```

로컬 전체 테스트는 SQLite CLI가 필요하다. 실제 컨테이너 격리, PostgreSQL fixture와
Chromium 동작은 Docker CI에서 별도로 확인한다. 구조 검사나 mock 응답만으로 실제 서버
검증이 완료됐다고 판단하지 않는다. fixture·로그·캡처에는 운영 비밀값을 사용하지 않는다.

## 검증의 한계

이 검토는 모든 입력 조합에서 결함이 없음을 증명하지 않는다. 자동 브라우저 검사는 Chromium
데스크톱·모바일 viewport를 사용하며 실제 모바일 기기·Safari·초심자 성공률은 측정하지 않는다.
브라우저의 07·08 최종 완료에는 테스트 fixture가 사용되지만 별도의 문제 smoke는 기존 풀이
경로를 실제 실행한다. 대규모 동시 참가 부하·학교 네트워크·외부 TLS 프록시·운영 DB 백업 복원은
실제 배포 환경에서 별도 리허설이 필요하다. 현재 단일 backend와 문제 서비스 인스턴스라는
운영 경계도 유지한다.
